# 验收与开发

## 本地自动化检查

在独立虚拟环境安装运行依赖及 `pytest pytest-asyncio ruff PyYAML`，执行：

```console
python -m pytest -q
python -m ruff check .
```

默认测试不使用真实 API Key、不执行付费请求。CI 在 Windows/Linux、Python 3.12/3.13 运行测试、Ruff 及元数据/配置一致性检查。

`tests/test_bridge.py` 使用明确的 AstrBot 4.29.4 契约替身，只能证明桥接逻辑；不能称为真实 AstrBot 加载、完整 Agent 或 QQ 集成通过。`tests/test_schema.py` 检查原生配置字段与运行默认值一致。

可选真实框架检查：在具备 AstrBot 依赖的独立环境，将固定 AstrBot 源码加入 `PYTHONPATH`，设置 `OPENAI_NATIVE_REAL_ASTRBOT=1`，运行：

```console
python -m pytest tests/test_bridge.py tests/test_real_execution.py tests/test_page.py -q
```

`tests/test_real_execution.py` 使用真实 `FunctionToolExecutor` 和权限包装，通过模拟 HTTP 走通搜索、Images 生成、multipart 编辑、原生 GIF、结果落盘和投递；不访问真实账号。它另验证人格禁用和权限拒绝。`tests/test_page.py` 检查保存冲突、失败回滚、秘密替换和能力清除；宿主路由检查基于指定源码的实际注册和请求绑定实现，可通过 `OPENAI_NATIVE_ASTRBOT_SOURCE` 指定源码目录。浏览器使用模拟宿主数据检查页面草稿与主题，不能称为真实 AstrBot 面板登录流程通过。

CI 对最低版本 4.29.4 和固定 master 提交执行框架注册、执行器及配置接口检查。模型是否会在真实聊天中选择工具、网关账号支持情况和 QQ/GIF 显示仍需下表验收。


## 发布前真实验收

以下均尚未在本次开发中使用真实账号或聊天平台验证。每项记录：日期、插件/框架/网关版本、模型、渠道和账号类型、请求数、费用上限、脱敏错误及结果证据。

| 环境 | 需要验证 |
| --- | --- |
| OpenAI 官方 API | Responses 搜索及引用、Images 静态生成与编辑、Responses 生图、获准账号原生 GIF |
| Sub2API | 实际使用的 API Key/OAuth/setup token/PAT 账号路径与权限差异 |
| NewAPI | Codex、Sub2API、兼容 Images 渠道分别记录支持/不支持，不相互推导 |
| 完整部署链路 | Sub2API → NewAPI → AstrBot 的参数、结果、错误透传 |
| 默认 Agent / Angel Heart | 自主调用、人格禁用、真实参考图、背景任务完成 |
| QQ / NapCat | 原始 GIF 动画、文件大小限制、延迟发送、失败后不重复生成 |

## 必测行为

1. A/B/C/D Provider 下拉与“当前会话”；聊天从 A fallback B 后插件仍访问绑定的 A。排队期间修改会话不改变已提交任务。
2. 两个用户、两个群、同用户跨群与私聊：引用图和任务所有权不串，群聊用户额度跨群累计，私聊单独。
3. 搜索只接受实际搜索执行证据；URL 引用可用，缺摘要留空，上游综合内容标记为不可信资料。
4. 当前图、引用图、两参考图、两输出；缺参考图不从群历史猜测，输入动画不静默取首帧。
5. PNG/JPEG/WebP/GIF 文件魔数与实际格式一致；GIF `n_frames > 1`、帧参数符合实际输出，发送前后原始文件未重新编码。
6. 同结果 URL 下载失败重试仍只有一次生成 POST；响应截断或超时标记待核对，不换 Key、模型或协议重发。
7. 排队取消、执行中取消、重启、部分成功、结果暂不可取和投递失败：额度结算幂等，不重复扣除或退款。
8. 公共 API 不自动发消息；等待超时不取消；管理员探测只有明确确认才提交。
9. 日志和聊天错误不出现 API Key、认证头、签名下载链接等信息。

## 故障核对

优先查看原任务状态。已生成但未下载：执行管理员 `retry-download`。执行情况未知：在上游账单或记录确认后使用 `reconcile` 填实际文件数。不要仅因客户端超时填 0，也不要用新任务“试一下”。任务完成和消息投递是不同状态。

## 交付状态

项目以独立 Apache-2.0 源码交付到 timeance/astrbot_plugin_openai_native。完整第一版在本地验收后提交 Draft PR；发布与部署仍需单独授权。上表中没有实际账号证据的能力保持实验标记。


## 0.1.1 本地开发版

本轮新增固定 `/生图`、`/生动图`、`/生图任务`、`/生图取消`，修正无任务时仍暴露任务查询工具的问题，详细配置移至插件页面。原始搜索失败缺少上游错误证据，未断言已确认其原因；新版通过请求与执行诊断帮助定位。

浏览器检查采用隔离 Edge 与模拟 bridge，覆盖深/浅主题、主题持久化、1440/768/390 像素五个分区、供应商选择、局部保存、手动重载提示、密钥显式替换、诊断刷新，以及冲突/保存失败保留草稿。没有发起真实计费请求。


## 0.1.2 自然语言生图修正

2026-11-10 的用户日志显示，`openai_image` 连续六次在本地校验阶段被拒绝：静态 PNG 被填入 GIF 帧参数，`resolution` 被填为 `auto`，或同时给出固定尺寸与比例。未创建任务，未提交付费 POST。模型随后将参数错误描述为服务不可用，与此前固定命令成功投递的图片混在一起。

本版为条件选填参数提供可空 Schema、合法比例格式及分辨率/质量枚举；在 LLM 入口归一化空值和旧调用中的 `auto` 占位，静态图忽略不适用的帧参数。GIF 保留显式帧值和严格范围检查。固定尺寸与比例的真实冲突继续拒绝；命令和公共 API 的严格校验保持原样。本地参数错误返回明确说明，不能自动重试已提交的任务。

回归覆盖日志中的完整静态参数、所有选填项显式传 null、GIF 帧参数、默认 GIF、无效零帧、尺寸冲突、未占额度和未发出重复 POST。真实 AstrBot 执行器配合模拟上游，验证从权限包装、过滤后 Schema、任务提交到原文件投递的完整链路。

用户提供的同日实测证据已确认其部署环境有 Alpha 搜索输出、固定命令静态生成及参考图编辑投递。尚缺完整入口/模型/版本信息，不能据此把全部兼容矩阵标为通过；原生 GIF 目前只有任务接受证据，生成结果及 QQ/NapCat 动画显示仍未确认。插件 Agent 未调用真实计费 API。
