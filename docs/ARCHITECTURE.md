# 实现结构

插件只提供工具及公共 API，不运行自己的聊天 Agent。所有入口共享 `NativeService`，身份来自真实事件。

| 文件 | 责任 |
| --- | --- |
| `main.py` | AstrBot 生命周期、工具、请求过滤、图片缓存、命令及原始文件投递 |
| `native/identity.py` | 平台实例、机器人、发送者、群和会话身份 |
| `native/providers.py` | 当前会话/指定 Provider/手动 API，固定连接快照及服务识别证据 |
| `native/capabilities.py` | 按连接指纹、模型、协议和格式保存能力观察与脱敏错误 |
| `native/transport.py` | 付费 POST 单次提交、SSE 完成判定、隔离且有限的 GET 下载 |
| `native/adapters.py` | Alpha、Responses Search、Images、Responses Image 协议 |
| `native/assets.py` | 参考图复制和归属、结果回执、格式校验、原始文件保存与清理 |
| `native/store.py` | SQLite 任务、预占、结算、幂等键与缓存素材的原子操作 |
| `native/service.py` | 校验、统一额度、队列、取消、恢复、后台投递与管理员核对 |
| `native/api.py` / `native/models.py` | 公共 API v1 与请求、结构化搜索、任务及结果类型 |
| `native/config.py` / `_conf_schema.json` | 默认值、校验与 AstrBot 原生配置界面 |

## 请求流程

可信事件身份 → 解析并固定供应商 → 校验请求和能力 → 准备参考图 → 原子额度预占与幂等检查 → 执行 → 保存已知结果数量和回执 → 下载与文件校验 → 结算 → 按入口选择投递。

图片以单图子请求执行多输出，每个已提交子请求单独保留执行边界，最多只有当前子请求存在未知完成情况。不会为凑齐数量重发失败的付费请求。

## 状态与重启

`get_task()` 分开返回生成、文件、投递和额度状态。已确认输出数量先结算并记录完成位置，随后保存回执和文件。重启只恢复已有回执的下载，不重发付费 POST；未提交的排队任务取消退款，完成情况未知的已提交任务保留预占。

明确失败与未知执行分开。下载失败保留已生成数量和原结果凭据，管理员重新下载只执行 GET；人工核对不重新生成。能力缓存是辅助记录，其写入失败不能撤销成功任务的额度。

## 身份与权限

UMO 用于路由和原会话所有权；用户额度使用平台实例、机器人和真实发送者，群聊用户跨群累计，私聊独立。群聊同时预占群总量。两个 SQLite 连接的竞争也由事务串行化。

LLM 参数只包含请求内容，不允许身份、管理员标记、密钥、任意供应商或任意本地路径。公共 API 接受同进程可信插件的文件输入，但仍通过同一额度和所有权规则，且不发送消息。

## 工具过滤

标准请求钩子复制本插件工具的 Schema，保留权限包装及其他插件工具；不重新加入已被人格排除的工具。明确不可用的能力被过滤，执行入口再次校验。自定义 Agent 可显式使用 `public_api.build_tools(event)`。

## 验证边界

自动化测试使用本地协议模拟及真实 SQLite，并单独验证固定版本 AstrBot 的工具注册。真实账号、网关渠道、完整 Angel Heart 聊天及 QQ/NapCat 显示按 `VALIDATION.md` 实测；源码和注册通过不代表这些项目已经验收。
