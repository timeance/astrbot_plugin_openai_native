# AstrBot OpenAI 原生能力

将 OpenAI 网页搜索、图片生成与编辑、原生 GIF 注册为 AstrBot 工具。主模型可按聊天内容调用，其他插件也可通过 Python API 复用；聊天决策、人格、记忆和 Agent 主循环仍由 AstrBot 管理。

**当前为 0.1.4 本地验收版。** 自动化协议与桥接契约测试不等于真实账号测试；OpenAI、NewAPI、Sub2API 的实际账号能力，以及 QQ/NapCat 动画显示均需按 [验收清单](docs/VALIDATION.md) 验证。供应商或模型名称不是能力保证。

## 安装

需要 AstrBot **4.29.4 或更新版本**、Python **3.12 或更新版本**。项目仓库：https://github.com/timeance/astrbot_plugin_openai_native 。

1. 开发版优先使用随交付提供的 ZIP，在 AstrBot 插件管理中上传本地插件包；也可将完整源码放入 `data/plugins/astrbot_plugin_openai_native`。不要只复制 `main.py`。仓库代码尚在 Draft PR 时，不要从仅含初始文件的默认分支安装。
2. 在 AstrBot 使用的 Python 环境安装 `requirements.txt` 中的依赖，重新加载插件。
3. 在原生插件配置中完成快速开始：分别启用搜索/生图，选择来源和已有供应商，填写图片模型。详细设置进入插件页面，手动 API 的地址和 Key 也在该页填写。
4. 详细页保存后，除诊断日志设置立即生效外，其余改动需手动重新加载插件；概览会显示已保存与运行配置的差异。原生配置页沿用 AstrBot 自身保存及重载行为。确认聊天模型支持 Function Calling，且当前人格允许本插件工具。

插件独立运行，不依赖 Angel Heart 或其他生图插件。Apache-2.0 许可证见 [LICENSE](LICENSE)。

## 先选择供应商

搜索和生图各自独立设置 `mode`：

| mode | 用途 |
| --- | --- |
| `current` | 提交时读取当前会话所选 Provider，并固定本次任务 |
| `provider` | 从原生 Provider 下拉选择一个已有供应商 |
| `manual` | 独立配置 Base URL、Key 和模型 |

例如 AstrBot 有 A/B/C/D，聊天设置 A 失败后 fallback 到 B：插件明确绑定 A 就只使用 A；选择“当前会话”且提交时解析到 A，本次插件请求仍使用 A。不会跟随聊天 fallback。搜索可以绑定 C，生图绑定 D。

已有 Provider 的连接信息、环境变量解析后的 Key、代理和适用请求头直接复用。**图片模型必须明确填写**，不能把任意聊天模型当成图片模型；Responses 生图还需填写 `host_model`。配置示例见 [配置指南](docs/CONFIGURATION.md)。

## 能做什么

| 能力 | 接口 | 说明 |
| --- | --- | --- |
| 网页搜索 | Alpha Search / Responses `web_search` | 单个或多个查询、真实来源链接；不把普通模型正文当联网结果 |
| 静态图片 | Images / Responses `image_generation` | PNG、JPEG、WebP；生成、编辑、多参考图和多图输出 |
| 原生 GIF | Images API | 默认关闭，需要管理员启用及上游模型、渠道和账号权限 |
| 图片任务 | 插件本地任务队列 | 状态、取消、结果保存、失败核对及重新下载 |
| 插件间调用 | Python API v1 | 结构化搜索结果、任务和本地文件；调用方决定是否投递 |

GIF 由上游原生生成，不在本地逐帧合成。每次工具调用可以单独指定 `output_format`、尺寸、帧数及每帧时长。GIF 默认 9 帧、每帧 200ms；支持 2–16 帧、20–2000ms，时长按 10ms 量化。动画输入的逐帧编辑、视频生成和视频编辑不在本版范围。

参考图优先使用显式素材 ID，其次是当前消息和引用消息中的图片，最后是同一发送者在同一会话的近期图片。动图参考会提取首帧为静态 PNG，再由上游生成新图片或动画。不会跨用户或跨群扫描历史来猜测图片。引用图片获取失败时请重新发送，或由调用插件明确提供素材。

## 自然语言使用

- “查一下这个产品今天的官方价格，带来源链接。”
- “画一只坐在咖啡店里的柴犬。”
- 发送图片后说：“把这张图改成水彩风格。”
- 引用一张图片说：“让角色眨眼，生成循环 GIF。”

0.1.2 修正了自然语言生图的可选参数：未指定的尺寸、比例、分辨率和 GIF 帧设置可使用默认值，静态图片不会因模型误填帧参数而被拒绝。固定尺寸与比例/分辨率仍不能同时指定；本次参数错误会明确返回，不能据此判断整个服务不可用。

0.1.3 本地验收版增加插件页面的搜索触发与返回预算、绘图预设和可编辑的单行命令回执。搜索默认只响应明确搜索请求，一次 1 个查询、3 条结果、返回模型约 2000 字符；来源链接和引用标记默认不提供给模型。命令及自然语言的图片任务与搜索调用继续共用各自的个人和群额度。

0.1.4 支持动图首帧参考，并调整命令停止传播的时机，使 AstrBot 可以正常发送回执和结束命令追踪。插件页面新增持久任务列表和生成图库，首页分为搜索、生图两个区域，各自设置归到对应功能页。任务受理后的生成状态也可通过 `/生图任务 <任务ID>` 查询。

工具名为 `openai_web_search`、`openai_image`、`openai_image_task`。生图工具立即返回任务 ID，后台完成后发送保存的原始文件。公共 API 不主动发消息。默认 Agent 和 Angel Heart 的标准主聊天路径是兼容目标；绕过 AstrBot 工具链的自定义聊天插件需要显式集成。

## 固定生图命令

无需主模型参与，直接提交任务；当前消息或引用中有图片时自动编辑。

| 命令 | 用途 |
| --- | --- |
| `/生图 一只咖啡店里的柴犬` | 静态图片，默认 PNG |
| `/生图 柴犬立绘 16:9 2K 2` | 末尾指定比例、分辨率和数量 |
| `/生图 水彩画 --数量 2 --尺寸 1024x1024 --格式 webp` | 显式参数 |
| `/生图 柴犬 --预设 水彩` | 使用插件页面保存的绘图预设 |
| `/生动图 摇尾巴的小狗 --帧数 9 --帧时长 200` | 原生 GIF；时长单位毫秒 |
| `/生图任务` 或 `/生图任务 <任务ID>` | 本人当前会话任务列表或详情 |
| `/生图取消 <任务ID>` | 申请取消静态图或 GIF 任务 |

比例和分辨率可使用 `--比例 16:9 --分辨率 2K`；固定尺寸不能同时指定比例/分辨率。数量最多 4，实际还受管理员限制和上游能力限制。`/生图` 仅支持 PNG/JPEG/WebP，GIF 使用 `/生动图`。同名命令冲突会在概览提示，此时使用明确入口 `/onative image ...` 或 `/onative gif ...`。

## 配置和调用诊断

插件页面包含概览、任务、图库、搜索设置、生图设置和通用设置。首页分别显示搜索、生图的运行状态与保留任务统计，并提供对应设置入口；调用诊断和检查命令可按需展开。搜索和图片各自的个人、群组、私聊每日额度均放在对应设置页，0 表示不限。时区、管理员豁免与请求间隔放在通用设置。

任务页按功能、状态筛选并分页，展示真实任务记录的结果与投递状态。图库展示已保存的图片和 GIF，支持缩略图与大图预览；结果文件到期清理后会显示不可用。任务和图库接口要求登录 AstrBot 管理面板。供应商可选“当前会话”、已有 Provider 或手动 API，按所选方式展开字段。主题可跟随 AstrBot，或选择深色/浅色并记住选择。

“配置就绪”表示可以尝试正常调用；“账号实测通过”只来自成功请求的证据。当前会话没有请求记录时显示等待会话验证。图片模型缺失会明确提示生图尚未就绪；未验证的完整搜索和静态生图配置允许首次调用。GIF 需要单独启用。

最近诊断保留工具进入/离开请求、隐藏原因、执行工具和脱敏错误，不保存完整聊天。概览可开启滚动保存诊断日志，保存后立即生效；默认总量上限 100 MB，重启后保留，超限清理最旧日志。新建图片应调用 `openai_image`；`openai_image_task` 只在本人当前会话已有任务时提供。人格或 AstrBot 禁用的工具不会被插件强行加入；可在诊断中检查“未进入当前请求”。

详细页的“刷新概览”不会覆盖表单草稿；保存冲突或失败也保留输入。凭据只在明确更换时提交，读取页面不回传原始 Key。配置检查和清除能力记录不调用付费接口。诊断日志设置保存后立即生效，其余详细页配置须手动重载插件；若随后使用原生配置页，请重新打开原生表单再编辑，避免旧表单覆盖已保存设置。

## 管理命令

| 命令 | 用途 |
| --- | --- |
| `/onative status` | 管理员查看配置和能力状态 |
| `/onative probe <能力> confirm` | 管理员明确确认后执行可能计费的探测 |
| `/onative task [ID]` | 列出本人当前会话任务，或查询指定任务 |
| `/onative cancel <ID>` | 请求取消；已提交上游的请求不保证停止计费 |
| `/onative quota` | 查看当前身份额度 |
| `/onative retry-download <ID>` | 管理员重新下载已生成结果，不重新生图 |
| `/onative reconcile <ID> <实际文件数>` | 管理员按核实后的执行数量结算待核对任务 |
| `/onative search <搜索词>` | 直接搜索 |
| `/onative image <提示词> [参数]` | 等同 `/生图` |
| `/onative gif <提示词> [参数]` | 等同 `/生动图` |

`probe` 未明确输入 `confirm` 时只提示，不提交计费请求。支持的能力名称和状态以 `status`/服务返回为准。启动不自动执行付费搜索或生图。

## 额度与故障处理

默认群聊用户每日搜索 20 次、生图 3 个文件，用户额度跨群累计；每群同时有 200 次搜索和 30 个图片文件的总额度。私聊额度独立为 20/3。`0` 不限制；旧配置中的 `-1` 读取时也按不限制处理。旧配置若将 `0` 用作禁用，升级后须改用搜索或生图启用开关。日界默认 UTC，可设置 IANA 时区，例如 `Asia/Hong_Kong`。命令和自然语言工具共用这套额度。

生成已完成但下载或发送失败仍按已生成文件数结算。网络中断导致是否执行不明时，额度保持预占并等待管理员核对；**不要重复提交同一付费任务**。重新下载只读取原结果地址。队列中取消可释放额度，提交后的取消无法承诺上游退款。

默认结果文件保留 7 天、任务记录 30 天，待核对任务不自动清理。任务与结果保存在 AstrBot 的 `data/plugin_data/astrbot_plugin_openai_native`，应按机器人数据一起备份。

## 接入边界

- NewAPI 入口不代表所有渠道都支持 Images 或 GIF。研究基线中，直接 Codex 渠道不支持 Images 转换。
- Sub2API 不同账号类型的 Alpha、Responses、Images 路径不同；请求成功不能反推它使用了哪种隐藏上游。
- 官方 OpenAI 的 Alpha Search 不是通用 API Key 保证路径，默认使用 Responses 搜索。
- GIF 第一版仅走 Images，不静默改成 PNG，也不自动更换模型或协议。
- 公共 API 只接受可信 AstrBot 事件；同进程插件间不是恶意代码隔离边界。
